Android 原生 Activity 后台被杀问题 — 完整优化方案

适用场景：UniApp + 原生插件（Objective-C / Java），原生 Activity 退后台后被 OEM 系统（VIVO / OPPO / 小米 / 华为等）强制销毁。
环境：Android minSdkVersion 21，targetSdkVersion 33，compileSdkVersion 35

一、问题根因分析

1.1 第一层：singleTask 清栈（Activity 回退栈层面）

UniApp 宿主 Activity 在 AndroidManifest.xml 中由 DCloud 框架声明为 singleTask 启动模式：

<activity
    android:name="io.dcloud.PandoraEntryActivity"
    android:launchMode="singleTask" />

singleTask 的系统行为规则：当用户通过桌面图标或「最近任务」将 App 恢复到前台时，Android 会重新向该 Task 的根 singleTask Activity 投递 Intent，并销毁其上方所有 Activity（清空上层回退栈），导致原生 Activity 被 finish()。

触发链路：
UniApp 页面 → 启动原生 Activity
                      ↓
             [按 Home 键退后台]
                      ↓
         [从桌面图标 / 最近任务恢复前台]
                      ↓
  Android 向 singleTask 的 UniApp 宿主 Activity 投递 Intent
                      ↓
  singleTask 规则：清除其上所有 Activity → 原生 Activity 被 finish()
                      ↓
              回到 UniApp 页面（表现为"瞬间退出"）

1.2 第二层：OEM 进程级别管控（进程存活层面）

即使通过独立 Task 解决了 singleTask 清栈问题，国产 OEM 系统（VIVO FuntouchOS、OPPO ColorOS、小米 MIUI、华为 HarmonyOS 等）仍会对后台进程执行激进的进程级别杀死策略，与内存大小无关，属于系统级调度策略。

进程优先级 IMPORTANCE 值 OEM 处理方式
前台 Activity IMPORTANCE_FOREGROUND = 100 几乎不杀
可见 Activity IMPORTANCE_VISIBLE = 200 内存极低才杀
前台服务 IMPORTANCE_FOREGROUND_SERVICE = 125 OEM 基本不杀
后台缓存 IMPORTANCE_CACHED = 400 OEM 随时可杀

二、完整三层防护方案

第一层（回退栈层面）：独立 Task 隔离
  → 解决 singleTask 清栈导致的 Activity 被 finish() 问题

第二层（进程层面）：前台服务保活
  → 将进程优先级提升至 IMPORTANCE_FOREGROUND_SERVICE，OEM 基本不杀

第三层（用户授权层面）：电池优化豁免引导
  → 绕过 VIVO 等 OEM 的后台管控策略

兜底层（UniApp 端）：状态感知与自动恢复
  → 万一前三层失效，保证用户体验可恢复，不丢失操作上下文

三、第一层：独立 Task 隔离

3.1 修改 AndroidManifest.xml

为你的所有原生 Activity 添加独立的 taskAffinity 和 launchMode，使其运行在独立 Task 中，与 UniApp 宿主完全隔离：

<manifest ...>

    <application ...>

        <!-- 预检拍照页面 -->
        <activity
            android:name=".PreCheckPhotoActivity"
            android:launchMode="singleInstance"
            android:taskAffinity="com.yourpackage.native_task"
            android:exported="false"
            android:screenOrientation="portrait" />

        <!-- 质检列表页面 -->
        <activity
            android:name=".QualityCheckListActivity"
            android:launchMode="singleInstance"
            android:taskAffinity="com.yourpackage.native_task"
            android:exported="false"
            android:screenOrientation="portrait" />

    </application>

</manifest>

关键说明： - launchMode="singleInstance"：该 Activity 独占一个 Task，UniApp 宿主的 singleTask 清栈行为只影响同一 Task 内的上层 Activity，不同 Task 不受影响。 - taskAffinity 必须与应用主包名不同，建议加 .native_task 后缀以区分。

四、第二层：前台服务保活

4.1 创建前台服务 NativePageForegroundService.java

// NativePageForegroundService.java
import android.app.Notification;
import android.app.NotificationChannel;
import android.app.NotificationManager;
import android.app.PendingIntent;
import android.app.Service;
import android.content.Intent;
import android.os.Build;
import android.os.IBinder;
import androidx.annotation.Nullable;
import androidx.core.app.NotificationCompat;

public class NativePageForegroundService extends Service {

    private static final int NOTIFICATION_ID = 9527;
    private static final String CHANNEL_ID = "native_page_channel";

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        createNotificationChannel();
        Notification notification = buildNotification();
        startForeground(NOTIFICATION_ID, notification);
        // START_STICKY：进程被杀后系统会尝试重启服务
        return START_STICKY;
    }

    private void createNotificationChannel() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            NotificationChannel channel = new NotificationChannel(
                CHANNEL_ID,
                "服务进行中",
                NotificationManager.IMPORTANCE_LOW  // LOW：无声音，不打扰用户
            );
            channel.setDescription("正在进行车辆检查服务");
            channel.setShowBadge(false);

            NotificationManager manager = getSystemService(NotificationManager.class);
            if (manager != null) {
                manager.createNotificationChannel(channel);
            }
        }
    }

    private Notification buildNotification() {
        // 点击通知返回 App
        Intent returnIntent = getPackageManager()
            .getLaunchIntentForPackage(getPackageName());
        PendingIntent pendingIntent = PendingIntent.getActivity(
            this,
            0,
            returnIntent,
            PendingIntent.FLAG_UPDATE_CURRENT | PendingIntent.FLAG_IMMUTABLE
        );

        return new NotificationCompat.Builder(this, CHANNEL_ID)
            .setContentTitle("服务进行中")
            .setContentText("正在进行车辆检查，请勿关闭应用")
            .setSmallIcon(R.mipmap.ic_launcher)  // 替换为你的图标资源
            .setContentIntent(pendingIntent)
            .setOngoing(true)           // 不可被用户手动清除
            .setSilent(true)            // 静默通知
            .setPriority(NotificationCompat.PRIORITY_LOW)
            .build();
    }

    @Nullable
    @Override
    public IBinder onBind(Intent intent) {
        return null;
    }

    @Override
    public void onDestroy() {
        super.onDestroy();
        stopForeground(true);
    }
}

import android.os.Build;
import android.os.Bundle;
import androidx.appcompat.app.AppCompatActivity;

public class PreCheckPhotoActivity extends AppCompatActivity {

    // 标记是否为用户主动退出（点击返回 / 完成按钮）
    private boolean isUserInitiatedExit = false;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_pre_check_photo);
        // 解析参数
        parseParams(getIntent());
    }

    @Override
    protected void onResume() {
        super.onResume();
        // 进入前台时启动前台服务
        startNativeForegroundService();
    }

    @Override
    protected void onStop() {
        super.onStop();
        // 退入后台时服务继续运行，不停止
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        // 只有用户主动退出时才停止服务
        if (isFinishing() && isUserInitiatedExit) {
            stopNativeForegroundService();
        }
    }

    /**
     * 用户点击"完成"或"返回"时调用此方法退出
     */
    private void finishPage() {
        isUserInitiatedExit = true;
        stopNativeForegroundService();
        finish();
    }

        Intent serviceIntent = new Intent(this, NativePageForegroundService.class);
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            startForegroundService(serviceIntent);
        } else {
            startService(serviceIntent);
        }
    }

    private void stopNativeForegroundService() {
        Intent serviceIntent = new Intent(this, NativePageForegroundService.class);
        stopService(serviceIntent);
    }

五、第三层：引导用户关闭电池优化

对于 VIVO、OPPO 等管控特别激进的 OEM 机型，前台服务仍有被系统管控的可能，需要引导用户将应用加入电池优化白名单。

5.1 创建工具类 BatteryOptimizationHelper.java

// BatteryOptimizationHelper.java
import android.app.Activity;
import android.content.Context;
import android.content.DialogInterface;
import android.content.Intent;
import android.net.Uri;
import android.os.Build;
import android.os.PowerManager;
import android.provider.Settings;
import androidx.appcompat.app.AlertDialog;

public class BatteryOptimizationHelper {

    private static final String PREF_KEY = "battery_opt_requested";

    /**
     * 检查并引导用户关闭电池优化（只弹一次引导弹窗）
     */
    public static void requestIfNeeded(Activity activity) {
        if (Build.VERSION.SDK_INT < Build.VERSION_CODES.M) return;

        String packageName = activity.getPackageName();
        PowerManager pm = (PowerManager) activity.getSystemService(Context.POWER_SERVICE);

        if (pm != null && pm.isIgnoringBatteryOptimizations(packageName)) {
            return; // 已在白名单中，无需处理
        }

        // 判断是否已经引导过，避免重复弹窗
        boolean alreadyRequested = activity.getSharedPreferences("app_prefs", Context.MODE_PRIVATE)
            .getBoolean(PREF_KEY, false);
        if (alreadyRequested) return;

        // 弹出说明弹窗，获取用户理解后再跳转系统设置
        new AlertDialog.Builder(activity)
            .setTitle("优化应用体验")
            .setMessage("为确保检查过程不被系统中断，建议关闭本应用的电池优化限制。\n\n请在接下来的系统设置中选择「不优化」。")
            .setPositiveButton("去设置", (dialog, which) -> {
                markAsRequested(activity);
                openBatteryOptimizationSettings(activity, packageName);
            })
            .setNegativeButton("暂不设置", (dialog, which) -> {
                markAsRequested(activity);
            })
            .setCancelable(false)
            .show();
    }

    private static void openBatteryOptimizationSettings(Activity activity, String packageName) {
        try {
            Intent intent = new Intent(
                Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS,
                Uri.parse("package:" + packageName)
            );
            activity.startActivity(intent);
        } catch (Exception e) {
            // 部分 OEM 不支持直接跳转，退而跳转到通用电池设置页
            try {
                Intent intent = new Intent(Settings.ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS);
                activity.startActivity(intent);
            } catch (Exception ignored) {}
        }
    }

    private static void markAsRequested(Activity activity) {
        activity.getSharedPreferences("app_prefs", Context.MODE_PRIVATE)
            .edit()
            .putBoolean(PREF_KEY, true)
            .apply();
    }
}

5.3 在 UniApp 插件初始化时调用

// 在你的 UniModule 初始化阶段调用
public class WCStoreNativeModule extends UniModule {

    @UniJSMethod(uiThread = true)
    public void navigateTo(JSONObject options, UniJSCallback callback) {
        Activity activity = mUniSDKInstance.getContext() instanceof Activity
            ? (Activity) mUniSDKInstance.getContext()
            : null;
        if (activity == null) return;

        // 首次进入原生页面时引导关闭电池优化
        BatteryOptimizationHelper.requestIfNeeded(activity);

        // 后续跳转逻辑...
        String module = options.optString("module");
        Intent intent;
        if ("precheck_photo".equals(module)) {
            intent = new Intent(activity, PreCheckPhotoActivity.class);
        } else if ("quality_check_list".equals(module)) {
            intent = new Intent(activity, QualityCheckListActivity.class);
        } else {
            return;
        }

        intent.putExtra("params", options.optString("params"));
        activity.startActivity(intent);
    }
}

六、兜底层：UniApp 端状态感知与恢复

即使前三层防护全部失效，通过 UniApp 端的状态感知机制，在页面恢复时自动重建原生页面状态，避免用户数据丢失。

6.1 创建 Composable：useNativePageGuard.js

// composables/useNativePageGuard.js
import { ref, onUnmounted } from 'vue'
import { onShow } from '@dcloude/uni-app'

export function useNativePageGuard() {
    const STORAGE_KEY = 'native_page_state'
    const isInNativePage = ref(false)

    /**
     * 跳转到原生页面，同时持久化当前状态
     * @param {string} module - 模块名：'precheck_photo' | 'quality_check_list'
     * @param {object} params - 传给原生页面的参数
     */
    const openNativePage = (module, params) => {
        const plugin = uni.requireNativePlugin('WCStoreNativePlugin-WCStoreNativeModule')

        // 持久化状态（使用 storage 以防进程重启后 ref 丢失）
        const state = { module, params, timestamp: Date.now() }
        uni.setStorageSync(STORAGE_KEY, JSON.stringify(state))
        isInNativePage.value = true

        plugin.navigateTo({ module, params })
    }

    /**
     * 原生页面正常关闭时调用，清除状态
     */
    const onNativePageClose = () => {
        isInNativePage.value = false
        uni.removeStorageSync(STORAGE_KEY)
    }

    /**
     * App 从后台恢复，检测原生页面是否被销毁
     * 若已销毁，根据业务决定是否自动重新打开
     */
    onShow(() => {
        try {
            const savedStateJson = uni.getStorageSync(STORAGE_KEY)
            if (!savedStateJson) return

            const savedState = JSON.parse(savedStateJson)

            // 原生页面已被销毁（否则不会触发 UniApp 页面的 onShow）
            console.warn('[NativePageGuard] 原生页面已被系统销毁，上次状态：', savedState)

            // 清除旧状态，防止下次 onShow 误触发
            uni.removeStorageSync(STORAGE_KEY)
            isInNativePage.value = false

            // 业务决策：可选择自动重新打开，或弹窗提示用户
            // 自动重新打开：
            // openNativePage(savedState.module, savedState.params)

            // 提示用户（推荐）：
            uni.showModal({
                title: '提示',
                content: '检查页面因系统限制被关闭，是否重新进入？',
                confirmText: '重新进入',
                cancelText: '取消',
                success: (res) => {
                    if (res.confirm) {
                        openNativePage(savedState.module, savedState.params)
                    }
                }
            })
        } catch (e) {
            console.error('[NativePageGuard] 状态恢复失败：', e)
        }
    })

    onUnmounted(() => {
        // 页面销毁时（非原生页面场景）清理状态
        if (!isInNativePage.value) {
            uni.removeStorageSync(STORAGE_KEY)
        }
    })

    return {
        isInNativePage,
        openNativePage,
        onNativePageClose
    }
}

九、注意事项

  1. 前台服务通知（Android 13+）：Android 13（API 33）起，展示通知需要 POST_NOTIFICATIONS 运行时权限。如果未获得权限，前台服务仍会运行，但通知栏不会显示。建议在应用启动时申请此权限。

    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
    ActivityCompat.requestPermissions(activity,
        new String[]{Manifest.permission.POST_NOTIFICATIONS}, 100);
}

  2. foregroundServiceType 兼容性：specialUse 类型从 Android 14（API 34）开始强制要求，targetSdkVersion 为 33 时暂不强制，但建议提前声明以备升级。

  3. 前台服务的启停时机：务必在 onResume 启动、在用户主动退出（isFinishing() && isUserInitiatedExit）时才停止，切勿在 onPause 或 onStop 中停止，否则退后台时服务会被关闭，失去保活效果。

  4. iOS 端无此问题：iOS 的 App 生命周期管理机制与 Android 不同，不存在 singleTask 清栈和 OEM 激进杀进程问题，iOS 原生插件无需针对此场景处理。
