原生 Activity
后台被杀 完整解决方案

针对 UniApp 原生插件场景下，退后台再恢复时原生 Activity 被系统销毁的问题，从 Activity 回退栈、进程保活、OEM 电池策略三个层面提供完整防护。

minSdkVersion 21
targetSdkVersion 33
compileSdkVersion 35
Java · Objective-C
01

问题根本原因

后台被杀问题实际上由两个独立的根因叠加造成，必须分层解决：

根因 A · Activity 层
singleTask 清栈
DCloud 宿主 Activity 被声明为 singleTask，从桌面图标恢复时 Android 会销毁其上所有 Activity。
根因 B · 进程层
OEM 激进进程管控
VIVO / OPPO / 小米等 OEM 对后台进程执行激进的系统级调度，与内存大小无关。

独立 Task 方案建立后的问题结构

使用 singleInstance + 独立 taskAffinity 解决了清栈问题后，会引入新问题：

// Task 结构示意
Task A（主 Task，与桌面图标绑定）
└── UniApp PandoraEntryActivity ← Launcher Icon 关联的是这个 Task
Task B（native_task，独立隔离）
└── 你的 NativeActivity ← 存活，但桌面图标不知道它
⚠️
新问题：点击桌面图标不恢复原生页面
Launcher 查找与包名关联的最近前台 Task，始终指向 Task A。Task B 的 NativeActivity 虽然存活，但被晾在后台。

解决思路：NativeActivity 启动时记录自身 taskId，UniApp 页面 onShow 时调用插件检测并通过 moveTaskToFront 主动拉回前台。
02

三层防护 + 兜底策略

第一层 · 回退栈
🛡 独立 Task 隔离
singleInstance + 独立 taskAffinity，与 UniApp 宿主完全隔离，解决清栈问题。
第二层 · 进程
🔋 前台服务保活
进入原生页面时启动前台服务，将进程优先级提升至 FOREGROUND_SERVICE，OEM 基本不杀。
第三层 · 系统授权
⚙️ 电池优化豁免
引导用户关闭电池优化限制，绕过 VIVO 等 OEM 的激进后台管控策略。
兜底层 · UniApp 端
🔄 状态感知恢复
onShow 时调用插件检测 Task 状态，存活则拉回前台，被杀则引导用户重新进入。
03

第一层：独立 Task 隔离

为所有原生 Activity 添加独立的 taskAffinity 和 launchMode，使其运行在独立 Task 中，与 UniApp 宿主 Activity 完全隔离。

📄 AndroidManifest.xml（Activity 声明部分）
XML 
<!-- 预检拍照页面 -->
<activity
    android:name=".PreCheckPhotoActivity"
    android:launchMode="singleInstance"
    android:taskAffinity="com.yourpackage.native_task"
    android:exported="false"
    android:screenOrientation="portrait" />

<!-- 质检列表页面 -->
<activity
    android:name=".QualityCheckListActivity"
    android:launchMode="singleInstance"
    android:taskAffinity="com.yourpackage.native_task"
    android:exported="false"
    android:screenOrientation="portrait" />
taskAffinity 必须与应用主包名不同，建议加 .native_task 后缀。singleInstance 保证该 Activity 独占一个 Task，不受主 Task 清栈行为影响。
04

第二层：前台服务保活

进入原生页面时启动前台服务，将进程优先级从 IMPORTANCE_CACHED（随时可杀）提升至 IMPORTANCE_FOREGROUND_SERVICE（OEM 基本不杀）。

NativePageForegroundService.java

☕ NativePageForegroundService.java
JAVA 
public class NativePageForegroundService extends Service {

    private static final int NOTIFICATION_ID = 9527;
    private static final String CHANNEL_ID = "native_page_channel";

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        createNotificationChannel();
        Notification notification = buildNotification();
        startForeground(NOTIFICATION_ID, notification);
        // START_STICKY：进程被杀后系统尝试重启服务
        return START_STICKY;
    }

    private void createNotificationChannel() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            NotificationChannel channel = new NotificationChannel(
                CHANNEL_ID,
                "服务进行中",
                NotificationManager.IMPORTANCE_LOW // 无声音，不打扰用户
            );
            channel.setDescription("正在进行车辆检查服务");
            channel.setShowBadge(false);
            NotificationManager manager = getSystemService(NotificationManager.class);
            if (manager != null) manager.createNotificationChannel(channel);
        }
    }

    private Notification buildNotification() {
        Intent returnIntent = getPackageManager()
            .getLaunchIntentForPackage(getPackageName());
        PendingIntent pendingIntent = PendingIntent.getActivity(
            this, 0, returnIntent,
            PendingIntent.FLAG_UPDATE_CURRENT | PendingIntent.FLAG_IMMUTABLE
        );

        return new NotificationCompat.Builder(this, CHANNEL_ID)
            .setContentTitle("服务进行中")
            .setContentText("正在进行车辆检查，请勿关闭应用")
            .setSmallIcon(R.mipmap.ic_launcher)
            .setContentIntent(pendingIntent)
            .setOngoing(true)   // 不可被用户手动清除
            .setSilent(true)    // 静默通知
            .setPriority(NotificationCompat.PRIORITY_LOW)
            .build();
    }

    @Nullable
    @Override
    public IBinder onBind(Intent intent) { return null; }

    @Override
    public void onDestroy() {
        super.onDestroy();
        stopForeground(true);
    }
}

在 NativeActivity 中控制服务生命周期

⚠️
关键启停时机
务必在 onResume 启动，仅在用户主动退出时停止。切勿在 onPause 或 onStop 中停止，否则退后台时服务会关闭，失去保活效果。
☕ PreCheckPhotoActivity.java（服务控制部分）
JAVA 
public class PreCheckPhotoActivity extends AppCompatActivity {

    private boolean isUserInitiatedExit = false;

    @Override
    protected void onResume() {
        super.onResume();
        startNativeForegroundService(); // ✅ 进入前台时启动
    }

    @Override
    protected void onStop() {
        super.onStop();
        // ❌ 不在此处停止服务！退后台时要继续保活
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        if (isFinishing() && isUserInitiatedExit) {
            stopNativeForegroundService(); // ✅ 仅用户主动退出时停止
        }
    }

    /** 用户点击"完成"或"返回"时调用 */
    private void finishPage() {
        isUserInitiatedExit = true;
        clearNativeTaskState();
        stopNativeForegroundService();
        finish();
    }

    private void startNativeForegroundService() {
        Intent intent = new Intent(this, NativePageForegroundService.class);
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            startForegroundService(intent);
        } else {
            startService(intent);
        }
    }

    private void stopNativeForegroundService() {
        stopService(new Intent(this, NativePageForegroundService.class));
    }
}
05

第三层：引导关闭电池优化

对 VIVO 等管控特别激进的 OEM，引导用户将应用加入电池优化白名单，弹窗只出现一次不重复打扰。

☕ BatteryOptimizationHelper.java
JAVA 
public class BatteryOptimizationHelper {

    private static final String PREF_KEY = "battery_opt_requested";

    /** 检查并引导用户关闭电池优化（只弹一次） */
    public static void requestIfNeeded(Activity activity) {
        if (Build.VERSION.SDK_INT < Build.VERSION_CODES.M) return;

        String pkg = activity.getPackageName();
        PowerManager pm = (PowerManager) activity
            .getSystemService(Context.POWER_SERVICE);

        if (pm != null && pm.isIgnoringBatteryOptimizations(pkg)) return;

        boolean asked = activity
            .getSharedPreferences("app_prefs", Context.MODE_PRIVATE)
            .getBoolean(PREF_KEY, false);
        if (asked) return;

        new AlertDialog.Builder(activity)
            .setTitle("优化应用体验")
            .setMessage("为确保检查过程不被系统中断，建议关闭本应用的电池优化限制。\n\n请在接下来的系统设置中选择「不优化」。")
            .setPositiveButton("去设置", (d, w) -> {
                markAsRequested(activity);
                openSettings(activity, pkg);
            })
            .setNegativeButton("暂不设置", (d, w) -> markAsRequested(activity))
            .setCancelable(false)
            .show();
    }

    private static void openSettings(Activity activity, String pkg) {
        try {
            Intent i = new Intent(
                Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS,
                Uri.parse("package:" + pkg)
            );
            activity.startActivity(i);
        } catch (Exception e) {
            try { // OEM 不支持直接跳转时，退而求其次
                activity.startActivity(new Intent(
                    Settings.ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS));
            } catch (Exception ignored) {}
        }
    }

    private static void markAsRequested(Activity activity) {
        activity.getSharedPreferences("app_prefs", Context.MODE_PRIVATE)
            .edit().putBoolean(PREF_KEY, true).apply();
    }
}
06

Task 恢复：主动拉回前台

解决独立 Task 引入的新问题：点击桌面图标后只恢复主 Task（UniApp 页面），原生页面虽存活但不可见。

1
NativeActivity 启动时持久化 taskId
将当前 Task ID 写入 SharedPreferences，供后续检测使用。
2
插件中增加检测方法
读取 taskId，通过 getAppTasks() 确认存活状态，存活则调用 moveTaskToFront。
3
UniApp onShow 中调用检测
页面恢复时第一时间调用插件，根据返回结果决定拉回前台或触发兜底恢复。

Step 1：NativeActivity 持久化 taskId

☕ PreCheckPhotoActivity.java（taskId 持久化部分）
JAVA 
@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_pre_check_photo);
    saveNativeTaskState();
}

@Override
protected void onNewIntent(Intent intent) {
    super.onNewIntent(intent);
    setIntent(intent);
    saveNativeTaskState();
}

private void saveNativeTaskState() {
    getSharedPreferences("native_page_prefs", MODE_PRIVATE)
        .edit()
        .putInt("native_task_id", getTaskId())
        .putString("active_module", getIntent().getStringExtra("module"))
        .putBoolean("is_active", true)
        .apply();
}

private void clearNativeTaskState() {
    getSharedPreferences("native_page_prefs", MODE_PRIVATE)
        .edit()
        .remove("native_task_id")
        .remove("active_module")
        .putBoolean("is_active", false)
        .apply();
}

@Override
protected void onDestroy() {
    super.onDestroy();
    if (isFinishing() && isUserInitiatedExit) {
        stopNativeForegroundService();
    }
    // ⚠️ 非用户主动退出时不清除状态
    // 让 UniApp 端检测到"曾存活但被杀死"并触发兜底恢复
}

Step 2：插件中增加 checkAndRestoreNativePage 方法

☕ WCStoreNativeModule.java
JAVA 
/**
 * UniApp 的 onShow 中调用此方法
 * 
 * callback 返回值：
 *   { active: true }            - Task 存活，已拉回前台，UniApp 端无需处理
 *   { active: false }           - 无活跃 Native Task，正常情况
 *   { active: false, crashed: true } - 曾存在但已被杀，触发兜底恢复
 */
@UniJSMethod(uiThread = true)
public void checkAndRestoreNativePage(UniJSCallback callback) {
    Activity activity = mUniSDKInstance.getContext() instanceof Activity
        ? (Activity) mUniSDKInstance.getContext() : null;

    if (activity == null) { callback.invoke(buildResult(false, false)); return; }

    SharedPreferences prefs = activity.getSharedPreferences(
        "native_page_prefs", Context.MODE_PRIVATE);

    boolean isActive = prefs.getBoolean("is_active", false);
    int taskId = prefs.getInt("native_task_id", -1);

    if (!isActive || taskId == -1) {
        callback.invoke(buildResult(false, false)); // 正常情况，从未打开
        return;
    }

    if (isTaskAlive(activity, taskId)) {
        ActivityManager am = (ActivityManager)
            activity.getSystemService(Context.ACTIVITY_SERVICE);
        am.moveTaskToFront(taskId, 0); // ✅ 拉回前台
        callback.invoke(buildResult(true, false));
    } else {
        // Task 已死，清除状态并通知 UniApp 端触发兜底
        prefs.edit().remove("native_task_id")
             .putBoolean("is_active", false).apply();
        callback.invoke(buildResult(false, true));
    }
}

private boolean isTaskAlive(Activity activity, int taskId) {
    ActivityManager am = (ActivityManager)
        activity.getSystemService(Context.ACTIVITY_SERVICE);
    if (am == null) return false;
    // getAppTasks() 只返回当前应用的 Task，无需特殊权限
    for (ActivityManager.AppTask task : am.getAppTasks()) {
        if (task.getTaskInfo().taskId == taskId) return true;
    }
    return false;
}

private JSONObject buildResult(boolean active, boolean crashed) {
    JSONObject r = new JSONObject();
    try { r.put("active", active); r.put("crashed", crashed); }
    catch (Exception ignored) {}
    return r;
}

Step 3：UniApp 端 useNativePageGuard.js

🟨 composables/useNativePageGuard.js
JS 
import { ref } from 'vue'
import { onShow } from '@dcloude/uni-app'

export function useNativePageGuard() {
    const STORAGE_KEY = 'native_page_state'
    const plugin = uni.requireNativePlugin('WCStoreNativePlugin-WCStoreNativeModule')

    /**
     * 跳转到原生页面，同时持久化状态
     * @param {string} module - 'precheck_photo' | 'quality_check_list'
     * @param {object} params - 传给原生页面的参数
     */
    const openNativePage = (module, params) => {
        const state = { module, params, timestamp: Date.now() }
        uni.setStorageSync(STORAGE_KEY, JSON.stringify(state))
        plugin.navigateTo({ module, params })
    }

    /** 原生页面正常关闭时调用，清除状态 */
    const onNativePageClose = () => {
        uni.removeStorageSync(STORAGE_KEY)
    }

    onShow(() => {
        // 调用插件检测 Native Task 状态
        plugin.checkAndRestoreNativePage((result) => {
            if (result.active) {
                // ✅ Task 存活，已被拉回前台，无需处理
                return
            }

            if (result.crashed) {
                // ❌ Task 曾存活但已被杀死，触发兜底恢复
                const savedJson = uni.getStorageSync(STORAGE_KEY)
                if (!savedJson) return

                const savedState = JSON.parse(savedJson)
                uni.removeStorageSync(STORAGE_KEY)

                uni.showModal({
                    title: '提示',
                    content: '检查页面因系统限制被关闭，是否重新进入？',
                    confirmText: '重新进入',
                    cancelText: '取消',
                    success: (res) => {
                        if (res.confirm) {
                            openNativePage(savedState.module, savedState.params)
                        }
                    }
                })
            }

            // active=false, crashed=false：正常情况，从未打开原生页面
        })
    })

    return { openNativePage, onNativePageClose }
}

09

注意事项

📢
Android 13+ 通知运行时权限
Android 13（API 33）起，展示通知需要 POST_NOTIFICATIONS 运行时权限。未获权限时前台服务仍运行，但通知栏不显示。建议在应用启动时申请：

if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
  ActivityCompat.requestPermissions(activity, new String[]{Manifest.permission.POST_NOTIFICATIONS}, 100);
}
ℹ️
foregroundServiceType 兼容性
specialUse 类型从 Android 14（API 34）开始强制要求。当前 targetSdkVersion = 33 时暂不强制，但建议提前声明以备升级 target 时无需再改。
ℹ️
REORDER_TASKS 权限说明
REORDER_TASKS 在 API 31 中被标记为 deprecated，但对操作自身应用内 Task 依然有效且不受限制。部分 OEM 定制系统建议声明以防拦截。
✅
iOS 端无此问题
iOS 的 App 生命周期管理机制与 Android 不同，不存在 singleTask 清栈和 OEM 激进杀进程问题，iOS 原生插件无需针对此场景做任何处理。
🚫
不要在 onPause / onStop 中停止前台服务
只有在用户主动退出（isFinishing() && isUserInitiatedExit）时才停止前台服务。在 onPause 或 onStop 中停止会导致退后台时服务立即关闭，完全失去保活效果。
